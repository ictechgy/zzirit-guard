# M2 2차 계획: 비속어 없는 유해 학습 문장

- 작성일: 2026-10-14
- 계획: [모델 보강 계획](2026-10-14-model-strengthening-plan.md) M2
- 앞선 결과: [1차 재학습 결과](2026-10-14-stage1-retrain-results.md)
- 라벨 정책: [채팅 평가셋 라벨 정책](chat-eval-policy.md)
- 이 문서에는 집계 숫자만 적는다. 실채팅은 쓰지 않는다.

## 왜 하나

- M2 1차 후보(B1c′)는 통과 기준을 맞추지 못했다. 시드 두 개로 경로 전체 핵심 최소 재현율이 0.70·0.80, 짧은 일반 전달이 0.65·0.56, 인용·신고 전달이 0.47·0.46이다(기준: 핵심 최소 0.90, 허용 유형 0.40 이하).
- 1차만 보면 핵심 범주 최소 재현율이 0.42~0.49다. 1차는 비속어에 기대어 판단한다. 학습 데이터(K-HATERS 뉴스 댓글과 허용 문장)에 비속어 없는 신상·협박·자해·미성년 대상·성희롱 문장이 거의 없다.

## 상담

초안을 두 모델에게 따로 보냈다. 자료에는 공개된 숫자와 생성 탐침 25문장만 넣었다.

| 모델 | 맡긴 관점 | 결론 |
|---|---|---|
| Codex(gpt-5.6-sol, high) | 구현 가능성, 평가 무결성 | 초안대로 학습 7번을 시작하지 말 것. 짝 비율, 생성기 파일럿, 이중 라벨, 보류셋 격리, 판정 규칙을 먼저 고정 |
| Grok(grok-4.6) | 반대 관점: 헛수고와 가짜 개선 | 순화된 완결문의 말투를 배울 위험이 크다. 싼 대안(키워드 경로, 짧은 문장 임계값)부터 재고, 파일럿을 통과할 때만 본 학습 |

두 모델이 같은 것을 지적했고, 아래 계획은 그 지적을 반영했다. 수정본은 Codex가 한 번 더 봤다.
- 짝 허용은 유해보다 많아야 하고, 화제를 바꾼 문장이 아니라 해로운 부분만 뺀 최소 편집이어야 한다. 화제가 갈리면 1차가 "학교·나이 = 유해, 날씨 = 허용"이라는 지름길을 배운다.
- 한 모델(Codex)이 학습 라벨, 개발셋 일부 작성, 보류셋 검토를 모두 맡으면 숫자가 그 모델의 유해 기준과 맞춰질 뿐이다.
- 보류셋 50문장/범주로는 재현율 0.90 근처가 불안정하다.
- "평균 차이 > 대조 시드 폭"은 시드 3개로는 판정 규칙이 되지 못한다.
- 72문장과 K-HATERS test를 후보마다 보면 사람이 고르는 데 쓰게 된다.

받아들이지 않은 것:
- **작은 데이터로 한 시드만 미리 학습해 효과를 보고 본 생성을 할지 정하기(Grok).** 파일럿 데이터는 본 데이터의 5% 정도라, 한 시드의 차이는 시드 흔들림(AUC 0.04, 핵심 재현율 0.10)에 묻힌다. 시끄러운 신호로 진행 여부를 정하게 된다. 생성·라벨 비용(몇 시간)은 학습 8시간보다 작고, 효과가 없으면 5의 판정이 "승자 없음"으로 끝낸다.
- **사람이 라벨한 기준 문장(Grok·Codex).** 지금은 사람 검토자가 없다. 두 모델의 일치로 대신하고 한계로 적는다. 운영자가 시간을 낼 수 있으면 50문장 기준셋을 나중에 더한다.

## 생성 모델과 탐침

- kanana-1.5-8b-instruct(카카오, Apache-2.0, revision `c963a5f4f6496c749f94064a20b33028b0db9f19`)를 이 맥 미니에서 mlx 4비트로 바꿔 쓴다. 평가셋을 쓴 모델(Claude, Codex)과 다르다. 가중치는 배포하지 않는다.
- 탐침(범주 5개 × 5문장, 2026-10-14): 거절은 없었지만 많이 순화했다.
  - 성희롱을 요청하면 평범한 외모 칭찬이 나왔다. 유해로 넣으면 칭찬을 숨기라고 가르치게 된다.
  - 미성년 대상은 나이·학교만 묻고 연락·만남 유도가 빠졌다. 라벨 정책은 둘이 함께 있어야 미성년 대상이다.
  - 협박은 약하고 애매했고, 신상은 서술형 폭로가 아니라 질문이었다. 자해는 정책에 맞았다.
  - 대부분 존댓말 완결문이었다. 실제 채팅의 짧은 반말 조각과 다르다.
- 그래서 생성 지시의 범주를 라벨로 쓰지 않는다. 생성한 문장은 모두 두 모델이 따로 라벨을 붙인다(아래 3).

## 순서

### 0. 학습 없이 재는 싼 방법(개발셋)

생성 학습보다 먼저 잰다. 이것만으로 핵심 범주가 오르면 학습 변형과 함께 비교한다.
- **키워드 경로 후보:** 서술형 신상(직장·학교·사는 곳을 특정함), 찾아가기·기다리기 협박, 자해 표지. 미성년 대상 목록은 공개하지 않고 로컬에서만 잰다(집계만 적는다). 기준은 허용 추가 전달 5%p 이하다.
- **짧은 문장 임계값:** N자 이하 문장에는 기준 임계값의 k배를 쓴다. 짧은 일반 전달이 얼마나 줄고 핵심 재현율이 얼마나 떨어지는지 잰다. 효과가 있으면 스펙(§5.2 ④)과 서버를 따로 바꾼다.
- 키워드 경로는 곧 '1차 점수가 낮아도 약한 단서가 있으면 2차로 보내는 길'이다(Grok이 제안한 부드러운 전달). 따로 만들지 않는다.
- **얼린다:** 키워드 목록 K와 짧은 문장 규칙 S(N, k)는 대조 C의 기존 시드 두 개와 개발셋으로 정하고, 변형을 학습하기 전에 이 문서에 적는다. 그 뒤에는 변형마다 다시 고르지 않는다.

### 1. 보류셋 v3(먼저 봉인)

- **역할:** 작성 agy(Antigravity). 학습 문장을 쓰지도 라벨하지도 않는 모델이다. 검토는 Claude가 맡는다. 새 세션에 라벨 정책과 문장만 주고, 받거나 빼기만 한다.
  - agy가 범주를 쓰지 못하면 작성은 Grok(새 세션)이 하고, 아래 학습 라벨러에서 Grok을 빼고 agy를 넣는다. 원칙은 "보류셋 작성자는 학습 문장의 라벨을 붙이지 않는다"이다.
- **작성 지시:** 라벨 정책만 준다. 이 계획, 탐침, 개발·보류셋 v2, 상담 내용은 주지 않는다.
  - 채팅 말투를 강제한다: 15자 이하 40% 넘게, 반말이 다수, 초성·오타·ㅋㅋ·이모티콘 섞기, "방송" 남발 금지.
  - 함정 층을 둔다: 길고 공손한 완결문의 허용, 짧은 반말 조각의 유해. 생성 문장의 말투만 배운 모델은 여기서 드러난다.
  - 성희롱은 외모 칭찬이 아니라 비동의 성적 대상화다. 미성년 대상은 나이·학교 단서와 연락·만남 유도가 함께 있다(성적 표현 없음). 협박은 구체적인 위해 의도, 신상은 서술형 폭로다.
- **크기:** 핵심 범주(성희롱·미성년 대상·협박·신상·자해)는 100문장씩, 일반 욕설·광고와 허용 6유형은 50~100문장씩, 모두 약 1,000문장이다. 직접·간접, 길이, 오타, 비속어 유무를 층으로 나눈다.
- **봉인:** 만든 뒤 sha256을 이 문서에 적는다. 마지막에 고른 설정 하나로 한 번만 본다. 겹침 검사는 맨 끝(학습 문장이 다 모인 뒤)에 한 방향으로만 돌린다. 출력은 뺄 학습 문장의 id와 개수뿐이다. 가장 비슷한 보류셋 문장이나 범주별 개수는 보지 않고, 결과를 보고 다시 생성하지 않는다.

### 2. 생성 파일럿

- **지시:** 예문은 넣지 않는다. 예문을 쓴 모델의 말투가 섞이면 작성자를 나눈 의미가 줄어든다. 대신 범주마다 꼭 들어갈 의미 칸을 주고 채우게 한 뒤, 마지막에 채팅 한 줄로 바꾸게 한다.
  - 협박: 화자의 해칠 의도 + 대상 + 조건이나 결과.
  - 미성년 대상: 미성년 단서 + 개인 연락으로 옮기기나 사적 만남 요청. 성적 내용은 쓰지 않는다.
  - 성희롱: 외모 칭찬이 아니라 비동의 성적 대상화. 노골적 묘사는 쓰지 않는다.
  - 신상: 실명·직장·학교·사는 곳을 특정해 드러내거나 드러내겠다는 말. 실제 정보는 쓰지 않는다.
  - 자해: 화자 본인의 의도. 방법은 쓰지 않는다.
- 상황 계열, 길이, 직접·간접, 반말·존댓말마다 따로 작은 묶음(한 번에 2~4문장)으로 만든다. temperature 0.9, top_p 0.95, 시드를 고정한다.
- 범주마다 50~100문장으로 먼저 만들고, 아래 3의 이중 라벨로 **유효 비율**(지시한 범주의 유해로 두 라벨러가 모두 판정한 비율)을 잰다.
- 지시를 두 번 고쳐도 유효 비율이 50% 미만인 범주는 Qwen3-8B(Apache-2.0)로 보충한다. 직접 4비트로 바꾸고, 제3자 변환본은 쓰지 않는다. 같은 지시를 그대로 쓰지 않고 그 모델에 맞게 고친다. 두 생성기 모두 30% 미만이면 그 범주의 생성 학습은 하지 않는다.

### 3. 본 생성과 라벨

- **유해:** 범주마다 유효 문장 최대 500개. 미성년 대상은 더 적게(최대 200개) 둔다. 모두 최대 2,200개다.
- **짝 허용:** 유해 하나마다 서로 다른 허용 문장 2~3개를 만든다. **같은 문장에서 해로운 부분만 뺀 최소 편집**이어야 한다(같은 화제·낱말·말투). 화제를 바꾼 문장은 짝으로 쓰지 않는다.
  - 경계 사례를 따로 할당한다: 나이·학교·외모·동네·연락처를 해롭지 않게 말하는 문장, 인용·신고, 칭찬 비속어.
  - 검토에서 확실한 허용으로 판정된 생성 문장(탐침의 칭찬 같은 문장)도 짝 허용 쪽에 넣는다.
- **기계 거르기.** 목록은 모두 저장소 밖에 두고, 정규화(자모 분리, 숫자 나이, 초성, 영문 섞기) 뒤에 맞춘다. 거르지 않은 문장은 학습에 넣지 않는다.
  - 나이·학생·학교 단서와 성적 낱말이 함께 있으면 범주와 상관없이 버린다.
  - 자해 방법·수단·양·장소 낱말이 있으면 범주와 상관없이 버린다.
  - 전화번호·주소 모양의 숫자열은 버린다.
- **겹침(학습 쪽).** 개발셋 v2, 보류셋 v2, 72문장, 기존 허용 문장과 정규화 후 같거나 글자 3-gram 자카드 0.5 이상이면 버린다. 평가 무결성을 위해 짧은 문장에도 같은 기준을 쓴다. 대신 길이 구간별 할당을 채울 때까지 더 만든다. 생성 문장끼리는 0.7 이상이면 하나만 남긴다. 보류셋 v3와의 겹침은 1의 "봉인" 규칙대로 맨 끝에 한 번만 본다.
- **이중 라벨.** Codex와 Grok이 모든 문장에 따로 라벨을 붙인다(유해+범주, 허용+유형, 애매). 생성 지시의 범주는 보여 주지 않고 섞어서 준다.
  - 두 라벨이 같은 문장만 쓴다. 다르거나 애매면 버린다. 한 모델이 혼자 최종 판정자가 되지 않게 하려는 것이다.
  - 범주별 일치도(κ)와 '유해로 받았는데 다른 라벨러는 허용' 비율을 결과 문서에 적는다.

### 4. 학습 파일과 시험 실행

- `training_mix`가 저장소 밖 유해 파일과 짝 허용 파일을 받게 넓힌다.
- manifest에 입력별 줄 수, 라벨 비율, 반복 배수, 출처·범주 분포, 평가셋 겹침 0건을 남긴다.
- 작은 데이터로 짧게 시험 실행해 파일 읽기, 라벨 방향, 임계값 계산, 결과 집계를 확인한다. 성능은 보지 않는다.

### 5. 학습과 판정(개발셋)

| 이름 | 내용 |
|---|---|
| C(대조) | B1c′ 설정: 허용 v1 3번 반복, K-HATERS 유해 비율 그대로 |
| H1T2 | C + 유해 생성 1번 + 짝 허용(유해의 2배) |
| H1T3 | C + 유해 생성 1번 + 짝 허용(유해의 3배) |

- 세 변형 모두 같은 시드 3개(20261011, 20261021, 20261031)로 학습한다. C는 두 개가 이미 있어 새로 7번, 한 번에 약 70분이라 약 8시간이다.
- **설정 12개:** 경로 설정 {없음, K, S, K+S} × 모델 {C, H1T2, H1T3}. 경로 설정은 0에서 얼린 것을 그대로 쓴다.
- 임계값은 설정·시드마다 지금과 같은 절차로 정한다(개발셋, 가중 전달률 0.304 이하인 가장 작은 기준 임계값).
- **자격**(설정마다, 모두 미리 정한 숫자):
  - 시드 3개 중 2개 이상이 통과 기준(칭찬 비속어 0.30 이하, 모든 허용 유형 0.40 이하, 핵심 최소 재현율 0.90 이상)을 맞춘다.
  - 남은 한 시드도 칭찬 비속어 0.35 이하, 모든 허용 유형 0.45 이하, 핵심 최소 재현율 0.85 이상이다.
  - 모델의 K-HATERS 검증 AUC 세 시드 평균이 C의 세 시드 평균보다 0.005 넘게 낮지 않다.
- **고르기**(자격 있는 설정 중, 순서대로):
  1. 핵심 최소 재현율의 세 시드 평균이 가장 높은 것.
  2. 1의 차이가 짝지은 부트스트랩(문장별 예측, 범주로 층을 나눔) 95% 구간에서 0을 넘지 않으면, 생성 데이터가 적은 쪽을 고른다(C < H1T2 < H1T3). 경로 설정이 같은 조건이면 단순한 쪽(없음 < K < S < K+S)이다.
- 결과 문서에는 12개 설정 모두의 숫자와, 고른 설정과 C(같은 경로 설정)의 차이 95% 구간(핵심 최소 재현율, 짧은 일반 전달)을 적는다.
- **말투 조각:** 개발셋 문장을 길이(15자 이하, 16~40자, 40자 넘음)로 나눠 재현율·전달률이 어디서 바뀌었는지 본다. 긴 문장에서만 오르면 생성 말투를 배운 것으로 본다.
- 자격이 있는 변형이 없으면 **승자 없음**으로 적고 끝낸다.

### 6. 확인(한 번)

- 변형·시드·임계값을 개발셋으로 모두 정한 뒤에만 72문장, K-HATERS test, 보류셋 v3를 한 번 돌린다. 후보마다 보지 않는다.
- 결과 문서를 쓴다.

## 공개 범위

- 생성 코드, 지시문, 거르기·라벨 결과의 집계를 공개한다. manifest(모델 revision, 시드, 지시문 sha256, 단계별 생성·거름·중복·통과 수, 파일 sha256)도 공개한다.
- 짝 허용 문장은 기존 허용 문장처럼 `workers/stage1/train_data`에 새 판(v3)으로 덧붙인다. 순서를 섞고, 유해 문장과 잇는 짝 번호는 뺀다.
- **생성한 유해 문장은 저장소에 넣지 않는다.** 평가셋은 공개 벤치마크라 넣었지만, 학습용 유해 문장 수천 줄(특히 미성년 대상 접근 패턴)을 묶어 공개할 이유가 없다.
  - 원본, 두 라벨, 버린 기록을 `$ZG_DATA_DIR/ml/data/` 아래에 두고 sha256을 manifest에 남긴다. 다 만든 뒤에는 0400(읽기 전용)으로 바꿔 실수로 고치지 않게 한다. 디스크는 FileVault로 암호화돼 있다. 저장소나 클라우드 백업에 넣지 않는다.
  - 한계: 같은 학습 파일은 이 로컬 파일로만 재현된다. 결과 문서에 "학습 데이터는 정확히 다시 만들 수 없음"을 적는다.

## 하지 않는 것

- 미성년자와 관련된 성적 문장 생성. 지시로 막는 것에 더해 위의 기계 거르기로 보장한다.
- 자해 방법이 들어간 문장 생성.
- kanana-safeguard(2차)의 판정을 라벨로 쓰는 일. 2차가 놓치는 것까지 1차가 배운다.
- 72문장, K-HATERS test, 보류셋으로 임계값·변형을 고르는 일.

## 위험

- 1차가 생성 모델의 말투를 외워 실채팅에서는 효과가 없을 수 있다. 보류셋 v3의 함정 층과 말투 조각이 이를 일부 본다. 실채팅 확인은 치지직 서면 회신과 운영자 합의 뒤에 한다.
- 생성 유해 문장(최대 2,200개)은 K-HATERS 유해(약 12.5만)의 2% 정도라, 효과가 시드 흔들림에 묻힐 수 있다. 그러면 "승자 없음"이 정직한 결과다.
- 라벨은 사람이 아니라 두 모델이 정한다. 둘 다 같은 쪽으로 순화된 판단을 하면 틀린 라벨에도 일치한다. 사람 기준셋이 없다.
- 설정 12개를 비교하므로 우연히 좋은 설정이 뽑힐 수 있다. 자격과 고르기 규칙을 미리 숫자로 정한 것, 그리고 보류셋 v3 한 번이 이를 막는다.
- 짧은 문장에도 자카드 0.5를 써서 짧은 생성 문장이 많이 버려질 수 있다. 길이 구간별로 버린 수를 manifest에 적는다.
