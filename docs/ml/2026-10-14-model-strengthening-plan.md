# 모델 보강 계획(실채팅 없이 지금 할 수 있는 것)

- 작성일: 2026-10-14
- 대상: 판정 파이프라인의 ③~⑤단계(키워드 경로, 1차 분류기, 2차 kanana)([설계 스펙 §5](../superpowers/specs/2026-10-11-zzirit-guard-design.md))
- 출발점: [1차 분류기 학습 결과](stage1-classifier-results.md)
- 이 문서에는 집계 숫자만 적는다. 실채팅은 쓰지 않았고, 상담에도 보내지 않았다.

## 왜 지금 하나

- 1차 분류기가 거름망 역할을 못 한다. 스펙의 임계값 0.05에서 2차로 넘기는 비율이 K-HATERS 약 97%, 채팅 회귀 문장 약 96%다. kanana는 이 맥 미니에서 초당 10~15건이 상한이라, 피크(초당 수십 건)에 대기열이 넘친다.
- 원인은 두 가지다.
  - 칭찬·친근함의 비속어가 0.95~0.99를 받는다.
  - 학습 데이터(뉴스 댓글)에 없는 범주(광고·협박/신상·성희롱·자해)는 점수가 낮다.
- 실채팅으로 학습하거나 임계값을 맞추는 일은 치지직의 서면 회신 뒤에만 할 수 있다(스펙 §15 4단계). 채널 운영자와의 합의도 아직 없다. 그래서 공개 데이터, 직접 쓴 문장, 합성 데이터만으로 할 수 있는 일을 먼저 한다.

## 상담

같은 요약 자료를 네 모델에게 따로 보내 의견을 받았다. 자료에는 이 문서와 스펙에 이미 공개된 숫자만 넣었다.

| 모델 | 맡긴 관점 | 결과 |
|---|---|---|
| Codex(gpt-5.6-sol, high) | 구현 가능성, 과적합을 막는 평가 설계 | 사용 |
| Antigravity(agy) | 대안 설계, 공개 데이터·라이선스 | 사용(라이선스 사실 3건은 틀려서 아래 표로 바로잡음) |
| Grok | 반대 관점: 지금 하면 헛수고인 일, 숨은 실패 | 사용 |
| Devin | 1~3주 실행 순서, 워커·지표 연결 | 사용 |

### 네 모델이 모두 동의한 것

1. **72문장은 봉인한다.** 임계값·키워드·모델 선택에 쓰지 않고, 설정을 고정한 뒤 회귀 확인용으로만 본다. 문장별 오답을 보고 새 문장을 쓰는 것도 같은 누수로 본다.
2. **채팅 형식의 개발셋과 보류셋을 따로 만든다.** 문장마다 출처, 시나리오 계열, 어휘 계열을 기록한다. 계열이 겹치면 같은 셋에 넣는다. 임계값과 키워드는 개발셋으로만 정하고, 보류셋은 설정을 고정한 뒤 한 번만 본다.
3. **1차 분류기는 '2차 처리 용량 안에서 재현율을 지키는 거름망'으로 평가한다.** K-HATERS F1이 아니라 "2차로 넘기는 비율이 감당할 수 있는 최대치(F_max) 이하인가"와 "범주별 재현율"로 고른다. F_max는 대기열(300건, 15초)과 kanana 처리 시간으로 계산한다.
4. **첫 학습 변경은 '허용' 어려운 예제(hard negative)다.** 칭찬 비속어, 게임 속 공격 표현, 짧은 감탄, 인용·신고 문장처럼 욕설과 모양이 비슷하지만 숨기면 안 되는 문장을 넣는다. 학습 데이터의 유해 비율(73%)도 낮춘다.
5. **키워드 경로는 '추가로 넘기는 비율'의 예산을 정해 둔다.** 정규화(자모 분해, 숫자·기호 치환)를 거쳐 맞춘다. 허용 문장에서 추가로 넘기는 비율은 3~5%p 이하여야 한다.
6. **미루는 것:** 기반 모델 교체, kanana를 1차로 증류하는 일. kanana 판정은 정답으로 쓰지 않는다. kanana가 놓치는 것(암시적 협박, 신상, 광고)까지 1차가 그대로 배우기 때문이다.
7. **라이선스를 먼저 확인한다.** 비영리(NC)·변경 금지(ND)·표기 없음은 빼는 쪽으로 정했다. 운영자가 수익을 내는 채널에서 쓸 수 있기 때문이다.

### 갈린 것과 판정

| 쟁점 | 의견 | 판정 |
|---|---|---|
| 1차를 범주별 다중 출력으로 바꾸기 | Codex·agy 찬성, Grok·Devin 보류 | 이진 모델 개선(위 4번)을 먼저 하고, 같은 평가셋으로 다중 출력과 비교해 이길 때만 바꾼다. Codex 기준: 같은 전달률에서 핵심 범주 재현율이 10%p 이상 오르거나, 같은 재현율에서 허용 전달률이 20%p 이상 내려가야 한다 |
| 공개 혐오 데이터셋을 학습에 섞기 | agy 강하게 찬성, Codex 선별, Devin 보통, Grok 평가용으로만 | 기본 학습에는 넣지 않는다. 라이선스가 확인된 것만 출처별로 빼 보는 실험(leave-one-source-out)으로 효과를 본 뒤에 정한다. APEACH는 평가 전용 데이터셋이라 평가에 쓴다 |
| 무엇부터 할지 | Codex·Grok·Devin은 평가 체계부터, agy는 데이터부터 | 평가 체계부터. 평가가 없으면 데이터를 바꿔도 좋아졌는지 알 수 없다 |

### 한 모델만 낸 것 중 채택한 것

- 핵심 범주(성희롱·미성년 대상·협박·신상·자해)는 대기열이 넘쳐도 버리지 않는 우선 예산을 둔다(Codex). 스펙 §5.4의 우선순위를 범주 단위로 넓히는 일이라 워커 단계에서 반영한다.
- 미성년 대상 키워드 목록은 공개 저장소에 넣지 않는다(Grok). 운영자가 로컬에서 넣는다.
- '도움 필요' 표시가 게임 농담에 자주 뜨면 매니저가 무시하게 된다(Grok). 자해 키워드는 정밀도를 따로 잰다.
- 키워드 경로나 요주의 사용자로 올라온 항목에만 같은 사람의 직전 메시지 2~3개를 함께 보여 주는 실험(Grok·Devin). 워커를 만든 뒤에 한다.
- 신상 정보는 같은 카카오의 [kanana-safeguard-siren-8b](https://huggingface.co/kakaocorp/kanana-safeguard-siren-8b)(Apache-2.0)에 '개인정보' 범주가 있다(이 문서 작성 중 확인). 메모리 여유를 보고 나중에 비교한다.

## 단계

### M1. 평가 체계(이번 작업)

1. **라벨 정책 문서:** 범주와 허용 유형의 정의, 경계 사례 처리를 적는다. 사람이 읽고 같은 라벨을 붙일 수 있게 쓴다.
2. **개발셋·보류셋:** 범주 7개(일반 욕설·혐오, 성희롱, 미성년 대상, 협박, 신상, 자해, 광고)와 허용 유형 6개(칭찬 비속어, 게임 속 공격 표현, 짧은 감탄·일반, 긴 일반, 인용·신고·부정, 숫자·주소 모양의 정상 문장)로 층을 나눈다.
   - 두 셋은 서로 다른 모델이 쓰고, 다른 모델이 라벨을 검토한다. 작성 모델의 말투를 정답의 단서로 배우지 않게 하기 위해서다.
   - 72문장과 겹치면 뺀다: 정규화 후 같은 문장, 또는 글자 3-gram 자카드 유사도 0.5 이상.
   - 미성년 대상 범주는 노골적인 성적 표현 없이 접근·유인 패턴(나이 묻기, 개인 연락 유도)으로만 쓴다.
3. **용량 계산기:** 대기열(300건, 15초 만료)과 kanana 처리 시간(스파이크 중앙값 98ms, p95 131ms)으로, 초당 10·20·30·50건에서 버림 1% 미만과 대기 p99 10초 미만을 지키는 최대 전달률 F_max를 낸다.
4. **채팅 평가 도구:** 개발셋·보류셋에서 범주별 재현율, 허용 유형별 전달률, 가정한 트래픽 구성으로 가중한 전달률을 임계값별로 낸다.
   - 트래픽 구성 가정(Grok 제안): 짧은 일반·게임 80%, 칭찬 비속어 12%, 광고 모양 5%, 유해 3%. 실측 전까지의 가정일 뿐이고, 섀도 운영으로 실제 비율을 재면 바꾼다.
5. **지금 모델의 기준선:** 위 도구로 지금 1차 분류기(B0)의 숫자를 남긴다.

### M2. 1차 분류기 재학습

- 학습용 허용 문장(2천~5천)과 약한 범주의 유해 문장을 직접 쓰거나 Apache-2.0 로컬 모델로 만든다. 개발셋·보류셋과 겹치지 않게 같은 검사를 한다.
- K-HATERS의 유해 비율을 낮춰(약 25~50%) 함께 학습한다.
- 통과 기준(개발셋으로 고르고 보류셋으로 확인):
  - 가중 전달률이 F_max 이하인 임계값에서, 칭찬 비속어 전달률 30% 이하(목표 20%), 어느 허용 유형도 40% 이하.
  - 핵심 범주의 경로 재현율(규칙·키워드·1차 중 하나라도 넘기면 성공) 목표 0.95, 최소 0.90.
  - 72문장 AUC가 지금보다 0.03 넘게 떨어지지 않는다(보고만 한다).
- 1차 결과: [재학습 결과](2026-10-14-stage1-retrain-results.md). 허용 쪽 기준은 보류셋에서 맞췄고, 핵심 범주 최소 재현율은 맞추지 못했다.

### M3. 키워드 경로와 워커

- 키워드 경로 기본 목록(미성년 대상 제외)과 정규화 변형별 평가. 허용 문장 추가 전달 5%p 이하.
- 1차 워커(127.0.0.1:8711)와 2차 워커(8712), 서버 연결, 범주별 우선 예산(스펙 §5.3·§5.4).
- 합성 트래픽 재생으로 대기열·버림·지연을 확인한다. 실채팅 섀도 운영은 서면 회신과 운영자 합의 뒤에만 한다.

### M4. 비교 실험(M2·M3 결과를 보고)

- 다중 출력 1차 모델, 공개 데이터 출처별 실험, kanana 프롬프트 변경, siren 비교, 키워드 경로 항목의 짧은 문맥.

## 지금 할 수 없는 것

- 실채팅으로 학습하거나 임계값·키워드를 맞추는 일.
- 실채팅 분포(비속어 비율, 광고 비율)를 아는 일. 위 트래픽 구성은 가정이다.
- 합성 문장의 성능이 실채팅에서도 그대로 나온다는 보장. 보류셋 숫자도 실채팅에서 다시 확인해야 한다.
