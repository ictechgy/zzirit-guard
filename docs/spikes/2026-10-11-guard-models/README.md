# 스파이크: 로컬 가드 모델 비교 (2026-10-11)

> **버리는 코드다.** `scripts/`는 재측정할 때 참고하려고 남겼다. 제품 코드가 아니다.

## 질문

1. 맥 미니(M4 Pro 12코어 CPU·16코어 GPU, 메모리 24GB, 273GB/s)에서 한국어 가드 모델을 실시간 방송 채팅에 쓸 수 있는가?
2. 피크에 초당 수십 건 이상 채팅이 들어오는 채널을 감당하려면 무엇이 필요한가?

## 방법

- 모델
  - `kakaocorp/kanana-safeguard-8b`(Apache-2.0)
  - `Qwen/Qwen3Guard-Gen-4B`·`0.6B`(Apache-2.0)
  - mlx-lm 0.32로 4비트·8비트 양자화
- 1차 분류기: `beomi/KcELECTRA-base`(MIT)를 K-HATERS train(CC-BY 4.0)의 이진 라벨로 2 epoch 미세조정. PyTorch MPS 사용
- 평가 데이터
  - `chat_samples.jsonl`: 직접 작성한 방송 채팅 72문장. 일반, 비속어, 모욕, 혐오, 성희롱, 협박·신상, 자해, 광고, 변형 욕설, 프롬프트 공격
  - K-HATERS test에서 라벨별로 100건씩 뽑은 400건(시드 20261011)
  - K-HATERS test 전체 1만 건(1차 분류기만)
- 측정 항목: 직렬 지연, 메모리, 묶음 처리량, 접두 KV 캐시(고정 템플릿 앞부분 재사용) 효과

## 결과 요약

| 구성 | 메모리 | 채팅 1건 중앙값 / p95 | 직렬 처리량 | 채팅 72문장 정밀도 / 재현율 |
|---|---|---|---|---|
| kanana-8b 4비트 + 접두 캐시 | 약 5GB | 98ms / 131ms | 9.7건/s | 0.97 / 0.77 |
| Qwen3Guard-4B 4비트 + 캐시 + 라벨만 생성 | 약 3GB | 232ms / 241ms | 4.3건/s | Unsafe만: 1.0 / 0.11, Controversial 포함: 0.88 / 0.64 |
| KcELECTRA 1차(CPU, 16개 묶음) | 약 0.5GB | 1건 11ms | 약 550건/s | (거름망 용도. 아래 참고) |

- **kanana 단독 상한은 초당 10~15건**이다. 묶음 처리 시 프롬프트 처리량이 약 350토큰/s이고, 접두 캐시 후 메시지당 약 23토큰이 남는다. 묶음 처리는 거의 효과가 없었다(3.4→4.3건/s).
- **Qwen3Guard는 탈락**했다. 홍어·틀딱·짱깨, 암시적 협박을 Safe로 판정했고, 칭찬성 비속어를 Controversial로 판정했다.
- **kanana가 놓친 것**: 단어 없이 하는 협박 3건, 실명·주소 신상 1건, 광고 3/4건 → 규칙이 맡아야 한다. 오탐은 "저 적팀 죽여버려!!"(게임 맥락) 1건이었다.
- **KcELECTRA 1차 분류기**(epoch-1): K-HATERS test에서 AUC 0.905, F1 0.90이다.
  - 욕설·혐오·변형 욕설은 0.9 이상으로 잘 올리고, 일반 채팅은 15문장 중 13개가 0.1 미만이다.
  - 성희롱·자해·협박·신상·광고는 점수가 낮아 놓친다(학습 데이터에 없는 범주).
  - 칭찬성 비속어는 높게 나와 kanana로 넘어간다.
- 맥북 네오(8GB)에서는 kanana 4비트가 들어가지 않는다(최대 5GB + OS). 직접 측정하지는 않았다.

## 한계

- 채팅 72문장은 직접 작성한 소량이라 편향이 있다. K-HATERS는 뉴스 댓글이다.
- 접두 캐시를 켜고 끄거나 4비트·8비트를 바꾸면, 경계 확률(약 0.5) 근처 판정 몇 건이 뒤집힌다.
- 실채팅의 비속어 비율과 중복 비율을 모르기 때문에 실제 kanana 부하는 아직 모른다.

## 파일

- `results/*.batch.json`: 묶음 처리량
- `results/kcelectra-e*.stage1.summary.json`: 1차 분류기와 2단계 시뮬레이션
