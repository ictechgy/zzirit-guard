# 채팅 평가셋(개발셋·보류셋)

> ⚠️ **이 폴더에는 욕설·혐오·성희롱·협박·자해 표현이 들어 있습니다.** 탐지 성능을 재려고 만든 합성 문장입니다. 실제 채팅이 아니고, 실존 인물의 이름·연락처·주소를 쓰지 않았습니다(전화번호는 지어낸 번호, 주소는 실제 구·동 이름에 지어낸 번지).

- 계획: [모델 보강 계획](../../../docs/ml/2026-10-14-model-strengthening-plan.md) M1
- 라벨 정책: [채팅 평가셋 라벨 정책](../../../docs/ml/chat-eval-policy.md)

## 파일

| 파일 | 쓰임 |
|---|---|
| `chat-dev-v1.jsonl` | 개발셋. 임계값·키워드·모델 선택에 쓴다 |
| `chat-holdout-v1.jsonl` | 보류셋. 설정을 고정한 뒤 확인용으로만 본다. 이 셋으로 임계값을 고르면 `evaluate_chat`이 오류를 낸다 |

## 만든 방법

1. 라벨 정책을 먼저 쓰고, 작성 모델에게 범주별 문장 수와 상황 계열 수를 정해 줬다. 작성 모델은 72문장 회귀 세트를 보지 않았다.
2. 개발셋과 보류셋은 서로 다른 모델이 썼다.
   - 개발셋의 신상·자해·광고와 허용 6유형: Claude(claude-opus-5.5)가 썼다.
   - 보류셋 전체: Codex(gpt-5.6-sol)가 썼다.
   - 욕설·성희롱·미성년 대상·협박: Claude 쪽 안전 필터가 작성을 막았다. 그래서 Codex가 쓴 문장을 상황 계열 기준으로 반씩 나눠 두 셋에 넣었다. 계열이 겹치지 않으니 누수는 없지만, 이 네 범주는 두 셋의 작성 모델이 같다.
3. 작성자가 아닌 모델이 라벨을 검토했다. Claude가 쓴 문장은 Codex가, Codex가 쓴 문장은 Claude가 봤다. 검토자가 라벨이나 범주에 동의하지 않은 문장은 넣지 않았다.
4. 미성년 대상 범주에서는 성적 의미로 읽힐 수 있는 요청(교복 사진 등)을 추가로 뺐다.
5. `uv run python -m zg_stage1.chat_eval_data eval_data/chat-dev-v1.jsonl eval_data/chat-holdout-v1.jsonl`로 겹침을 검사했다.
   - 검사 대상: 72문장, 두 셋 사이, 셋 안.
   - 기준: 정규화 후 완전 일치, 또는 글자 3-gram 자카드 0.5 이상. 숫자 사이의 점·콜론은 정규화에서 남긴다.
   - 걸린 문장은 뺐다.
   - 같은 작성자의 상황 계열이 두 셋에 걸치지 않는지, 애매 문장이 5% 이하인지, 범주마다 채점 문장이 20개 이상인지도 본다.
   - `tests/test_chat_eval_data.py`가 커밋한 두 파일에 이 검사를 모두 돌린다.

## 한계

- 합성 문장이다. 실제 채팅의 말투·신조어·비율과 다르다. 이 셋에서 나온 숫자는 실채팅에서 다시 확인해야 한다.
- 범주마다 21~60문장이라 범주별 재현율의 신뢰구간이 넓다(50문장에서 재현율 0.9이면 95% 구간 약 ±0.08).
- 라벨은 사람이 아니라 모델 두 개가 정했다. 사람 검토를 거치면 버전을 올린다.
